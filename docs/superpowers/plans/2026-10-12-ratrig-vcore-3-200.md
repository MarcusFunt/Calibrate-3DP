# RatRig V-Core 3 200 Profile Import Plan

> **For agentic workers:** Execute inline under the current user request. Keep the change task-sized and verify before marking the checkbox complete.

**Goal:** Save the supplied RatRig V-Core 3 200 printer, General(Slow) process, and Sunlu Black filament profiles in Calibrate-3DP's local library.

**Architecture:** Preserve the user-provided profile JSON in app-owned local files and use the existing profile resolver and SQLite library. Normalize Orca profile role aliases at import and allow a `printer` profile to inherit a `machine` parent, while retaining the original raw JSON and never writing to Orca's profile folders.

**Tech Stack:** Python 3.11, standard-library JSON/SQLite, unittest.

**Spec:** User-provided profile JSON in the 2026-10-12 request; project rules in `AGENTS.md`, `docs/V1_GOAL.md`, and `IMPLEMENTATION_PLAN.md`.

## Global Constraints

- Keep profile resolution independent of Qt.
- Import profiles read-only and preserve unknown keys and original profile data.
- Do not connect to the printer, activate profiles, or write to Orca source directories.
- Do not claim slicer compatibility or print readiness from profile import alone.
- Append evidence to `docs/PROGRESS_HISTORY.md` and update status after verified implementation.

## Review Focus

- `type: print` is recognized as a process role without losing the submitted raw value.
- Orca user preset files with no `type` are classified from their standard profile directory.
- `type: printer` resolves its `machine` parent and preserves inherited provenance.
- Parent profiles remain scoped and ambiguity still fails closed.
- The saved printer and material survive repository reload and source hashes match.
- Host fields remain stored metadata; no printer-control path is introduced.
