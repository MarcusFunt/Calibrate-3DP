## Implemented foundation

- Python >=3.11 headless core, existing profile import/inheritance resolution, provenance and unknown-key preservation, deterministic ironing plans, manual result contracts, and separate Orca jobs.
- Database schema v2 adds persistent printer, material, and grouped calibration-run records while preserving existing v1 session rows and payloads. Versioned profile snapshots retain raw documents, resolved values, provenance, and source fingerprints. Plan/sample data stays in SQLite; logs, 3MF, and G-code stay in per-run artifact folders with hashes and checked paths.
- Profile discovery/import and saved-record workflows connect to Qt. Users can add a printer from installed or local JSON/ZIP profiles, add nozzle-contextual filament records, reopen a printer workspace, start a nine-sample ironing run asynchronously, cancel it, inspect run history, and look up a run by its six-character code. Orca executable and profile roots are configurable in Settings.
- A standard-library 3MF writer packages nine Sample-A through Sample-I objects and a separate `Plate-Frame`; each sample object/part ID retains its own settings metadata. The grouped-run service uses the connected geometry backend, saves each STL and geometry manifest, and checks all nine ironing settings plus the ten-object shared layout in real Orca output. The CLI uses `--arrange 0 --orient 0`; post-slice validation compares each named object's XY extrusion bounds with its mesh bounds under one shared translation and rechecks the translated layout against the selected bed and keep-outs.
- The `stdlib-voxel` geometry adapter (0.4 mm grid) creates nine separately addressable watertight specimens, eight 2.4 × 0.8 mm breakaway links per sample, raised bitmap A–I labels, and a raised six-character code on the shared rail frame. It checks resolved machine bed polygons and explicit keep-outs, validates mesh closure/object mappings, and produces deterministic meshes. Binary STL and connected-mesh 3MF package tests pass locally.
- The Qt printer workspace reports geometry status, printed-mark presence, sample-settings and sliced-layout status, Orca identity/support qualification, and all remaining print-readiness blockers in both the active workspace and run history. It has no printer-control action; successful sample-settings/layout validation is still `print_ready: false`.
- Generation records the source and derived profiles, exact Orca argument vector, CLI banner, G-code header, logs, bounds, and artifact hashes. The run is marked `settings_validated`; `print_ready` remains false.
- The Orca CLI probe records the executable SHA-256/size, optional Windows file/product versions, raw help output, and `--version` output when that option is advertised. The observed CLI engine label `01.10.01.50` and G-code application label `2.3.0` are reconciled by the official v2.3.0 `version.inc`; the mapping does not authenticate the binary or establish printer support.
- The Dear PyGui shell and launch dependency are removed. Existing `app/pages` adapters remain transitional and are not exposed as the supported Qt workflow.
